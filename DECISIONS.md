- **D-002 (Phase 0) Python 3.12 venv, not system 3.14.** torch/neuraloperator wheels are most reliable on 3.12; a uv-managed CPython 3.12.13 was already on the machine.
- **D-003 (Phase 0) Budget interpretation.** The user said the presentation is in ~4 days and asked not to reduce scope unless necessary, "as long as the entire project compute fits in the next 1-2 days". Plan to the 12 GPU-h target, but allow up to ~24 h of wall-clock before applying the brief's automatic reductions (seeds, then Regime B, then ablations).
- **D-004 (Phase 0) torch 2.7.1+cu128.** The RTX 5070 Laptop GPU is Blackwell (sm_120), which needs CUDA 12.8 wheels.
- **D-005 (Phase 0) Compute tier: Tier 1 (local GPU, 8 GB VRAM), no Colab.** The PINN at 50k collocation points uses 1.8 GB. Colab T4s would be slower than this GPU.
- **D-006 (Phase 0) float64 PINN training is impractical on this GPU** (1.5 vs 18 Adam it/s, consumer FP64 rate). The f64 L-BFGS ablation will be one short run only.
- **D-007 (Phase 0) Taylor-mode (forward) derivative propagation for PINN residuals.** It is exactly equal to nested autograd (max diff ~1e-16 in float64, see tests/test_residuals.py) and 1.4-1.7x faster. Autograd stays as the reference path.
- **D-008 (Phase 0) Concurrent GPU jobs reduce total throughput** (3 jobs x 9.9 it/s < 1 job x 41 it/s at 20k points), so PINN runs go through the GPU sequentially. Cheap CPU work (SSFM, aggregation) runs in parallel.
- **D-009 (Phase 0.5) The equation convention matches Jiang et al.** Their Eq. 3, with beta2 → s, is algebraically our NLSE. The L_D and N² typos are confirmed (report/brief_corrections.md #1-2).
- **D-010 (Phase 0.5) Shortlisted technique 1: periodic Fourier-feature embedding in tau** (Wang, Sankaran & Perdikaris). It enforces the periodic BC of the SSFM window exactly. It lives in PINN+ (`models/pinn_plus.py`) and can be toggled for the ablation.
- **D-011 (Phase 0.5) Shortlisted technique 2: last-layer transfer / test-time fine-tuning** (Fesser et al. Sec. 4, following Pellegrin et al.). It is used only in the optional PINN-finetune model (Phase 9.3), where both full fine-tuning and last-layer-only are labelled. It is never used to touch splits.
- **D-012 (Phase 0.5) Novelty reframing for component A.** Fesser et al. already computed WF distances for the NLSE (single 2·sech time-extrapolation case, PINN only). Component A is therefore called an *extension* of Fesser et al.: parametric N-extrapolation, PINN vs data-driven, and a closed-form SPM bandwidth driver. It is not called novel. Component B (conservation drift as a label-free estimator) had no prior NLSE work in our searches, so "to our knowledge".
- **D-013 (Phase 0.5) PINN+ Fourier features are deterministic periodic harmonics by default**, as in the cited causal paper, not random. A random-feature option exists in config.
- **D-014 (Phase 0.5) Shortlisted technique 3: N-curriculum** (Krishnapriyan et al. curriculum regularization). It is held as a failure-handling fallback only and is not part of the main comparison unless training fails.
- **D-015 (Phase 1) Starter repo submodule pinned** at `a41e83879d5d1e992f93ba4188c454a2370b94ce` (xieyulai/fiber-nlse-pinn, MIT). Remote: https://github.com/ShreyasVR2545/ultrafast-pinn-extrapolation (private). No teammate invited (D-001).
- **D-016 (Phase 2) Repo reproduction scope.** fig3 and fig7 use 3 seeds; fig8 uses seed 0 only (8-segment decomposition, ~75 min per run at the README's 4586 s). It is a side reproduction, so its GPU time goes to the core study. More fig8 seeds run only if the GPU is idle later.
- **D-017 (Phase 3) One validated grid per regime, not one global grid.** Regime A at N=4 spreads to |τ|≈40, which needs τ_max=50. Regime B at N=3 needs fine dτ and dξ but not a wide window. Within a regime, all models use the same grid. A: τ∈[−50,50), 1024 pts, dξ=2e-4. B (sech and Gaussian): τ∈[−30,30), 2048 pts, dξ=1.25e-5. 201 saved slices over ξ∈[0,4]. Evidence in `results/grid_study.json`.
- **D-018 (Phase 3) Two tests were fixed by correcting the test setup, not by loosening tolerances.** (i) SSFM vs RK4IP: the original step sizes left SSFM's own truncation error (5e-6, measured to fall exactly 4× per halving) above the 1e-6 tolerance, so both integrators now run at converged steps. (ii) Grid PDE residual: the fixture's Δξ=0.05 slices gave a 4th-order FD floor of 1e-3; at the production Δξ=0.02 it is 2.8e-5. Tolerances are unchanged.
- **D-019 (Phase 4) Regime B is split into two sub-regimes, B_sech and B_gauss** (one parametric model per input shape), since the brief lists both inputs. Run directories are `runs/<sweep>/<exp>/<model>/<regime>/seed<k>`; split-level results live inside metrics.json rather than in separate split folders (the brief's layout had a split level).
- **D-020 (Phase 4) pinn_extended is not run in z_extrap.** All PINNs see ξ ≤ 2 in z_extrap (brief), so extended collocation in N adds nothing to the z question (pre-registered).
- **D-021 (Phase 6) Fairness = equal optimizer steps.** PINN family and DD-MLP: identical 4x100 tanh trunk, 10k Adam (lr 1e-3 → 1e-4 exponential, resample every 100) + 2k L-BFGS (strong Wolfe), 20k points per batch (Tier-2 setting). cFNO: the same 12k total steps (Adam), batch 32 fields. Wall-clock logged for all. Enforced by tests/test_fairness.py. The final step counts are fixed after the pilot.
- **D-022 (Phase 6) cFNO is conditioned on (N, ξ) as broadcast channels** (direct variant), so it can be queried at any ξ, including ξ > 2. It is run in both experiments. cFNO-AR uses 5-slice steps (Δξ = 0.1), residual form, and 1e-3 input-noise injection. Loss: per-sample relative L2.
- **D-023 (Phase 6) Each model's input normalization uses its own training input range.** PINN-extended: N ∈ [1, 4] (its label-free collocation range). Strict and DD: the train N range.
- **D-024 (Phase 6) The z_extrap evaluation also saves per-slice errors over all ξ** so the figure can show error growth across ξ=2. Every scalar metric uses only the pre-registered ξ ∈ (2, 4].
- **D-025 (Phase 6) The PINN pilot failed the in-distribution sanity check, and every diagnostic so far is logged here.** Regime A pinn_strict with 10k Adam + 2k L-BFGS and 20k points gave interp rel-L2 ≈ 0.42 and energy drift up to 0.48 (`runs/pilot/`). Diagnostics, all judged on the interp split only (no extrapolation data used):
  - PINN+ as configured: interp 0.57, worse.
  - τ-focused sampling (half the points drawn from N(0, 8²)): 0.28.
  - 3× steps (30k Adam + 6k L-BFGS): 0.25.
  - **Implementation check** (`scripts/06_pinn_check_fig3.py`), our code on the starter repo's single-N fig3 problem at the 12k-step budget: 16.8% at τ_max=24 and 22.9% at τ_max=50. The repo reaches 3% with ~25k L-BFGS iterations, and its residual loss reaches ~1e-5 against our ~2e-4. Working hypothesis: NLSE PINNs need long L-BFGS runs, and our budget is badly L-BFGS-starved. Being tested next with 2k Adam + 20k L-BFGS.
- **D-026 (Phase 6) Hypothesis confirmed: the budget was L-BFGS-starved, the code is not broken.** The implementation check with 2k Adam + 20k L-BFGS (20k points) reaches **3.5%** on fig3, against the repo's 3.0% and 2.8% (seeds 0 and 1), with residual loss 1.3e-5. It costs 1084 s per run. New schedule candidate for every MLP-based model: 2k Adam + 20k L-BFGS. PINN+ also gets an option to keep causal weights during L-BFGS (`plus.causal_lbfgs`), since L-BFGS now dominates training. Parametric Regime A is being re-piloted. Compute impact: ~18 min per PINN run, so the main study is ~14-18 GPU-h. That is above the 12 h target but inside the 1-2 day window the user allowed (D-003), so seeds are not cut.
- **D-027 (Phase 6) Schedule-2 pilot results (Regime A, seed 0, 2k Adam + 20k L-BFGS) and a PINN+ bug fix.**
  - DD-MLP: interp 1.8%, near 13%, far 148% (368 s).
  - PINN-strict: interp 15.7% (6.7-26%, grows with N), 1336 s.
  - PINN+: ~100% everywhere. **Cause: my causal schedule force-advanced ε every adam_steps/5 = 400 steps.** It reached ε=100 while per-bin residuals were ~1e-2, so min w ≈ 1e-20, which zeroed every ξ bin past the first. Keeping those weights in L-BFGS then froze the optimizer: the loss stayed constant for 20k iterations, and the run took 4019 s. **Fix:** ε advances only when min w > 0.99 (Wang et al.'s criterion; the forced advance is kept only as an opt-in flag). L-BFGS uses the last ε reached.
  - Also added: τ-focused sampling for the DD-MLP data sampler, so any sampling-density choice applies identically to the PINN and the DD-MLP.
- **D-028 (Phase 7 plan) Automatic scope reduction to fit ~1 day of GPU time** (brief order: seeds are already at the minimum of 3, then Regime B before A). Measured costs per seed: ~2.5 h per regime for both experiments. Plan: Regime A full (n_extrap + z_extrap, 3 seeds); B_sech full (3 seeds); **B_gauss n_extrap only** (z_extrap dropped unless time remains). Ablations come after, as far as the remaining time allows.
- **D-029 (Phase 6) PINN+ was overfitting its fixed L-BFGS collocation set.** With the corrected causal schedule, PINN+ reached the lowest training loss of any model (residual 1.6e-6, IC 1.9e-8) but still had 94% error. Its held-out mean-squared residual was 2.2e-2, about 10^4 times its training-batch value. PINN-strict shows no such gap (5.4e-5 train vs 6.5e-5 held out). The 98-dimensional periodic embedding can interpolate a fixed set of 20k points in (ξ, τ, N) without satisfying the PDE between them. **Fix, applied to every MLP model through the shared schedule:** a fresh L-BFGS batch with fresh optimizer state every 2000 iterations (`schedule.lbfgs_resample_every`). Two earlier τ-focus pilots crashed at startup because of a YAML quoting error in my override (`{frac:0.5}` parses as one key); they were rerun with correct quoting. Side note for analysis B: the DD-MLP has 1.5% field error but a held-out residual RMS of 1.6e-2, so residual size is a noisy error proxy.
- **D-030 (Phase 6) Frozen configuration** (`configs/models/shared.yaml`), chosen from Regime A seed-0 pilots on the **interp split only**: 2k Adam + 20k L-BFGS, with the L-BFGS batch resampled every 2k iterations, 20k points per batch, and τ-focused sampling (frac 0.5, σ=8) for the PINN family and DD-MLP alike. PINN+ keeps causal weights during L-BFGS. PINN+ has 40k parameters against 31k for the plain trunk, because the periodic embedding widens the first layer; depth and width are otherwise identical. PINN-extended was not piloted separately, since it is the strict configuration with a wider collocation N range.
